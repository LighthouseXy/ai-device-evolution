# 2026-07-30 开发日志

## AI 设备顾问链路精简

- 删除本地预算、性能、续航、屏幕、便携、存储和相机等多维加权评分。本地职责收敛为输入标准化、品类过滤、预算内与预算接近度排序、发布时间稳定排序、最多 8 个候选、官方事实整理和简单 rules fallback。
- rules fallback 明确只按设备类型、预算和发布时间排序，不再包装为完整需求分析。
- OpenAI / DeepSeek 使用紧凑候选协议：模型只返回候选 `deviceId`、`matchScore`、理由、权衡及顶层摘要、人群和可信度；型号、系列、类别、年份和价格由服务端候选真值补齐，未知 ID 会被过滤。
- 移除 AI 部分结果与规则结果拼接。合法完整输出统一标记为 `ai`；无法形成有效主推荐和备选时重试一次，仍不合规则完整回退为 `rules`。
- 七个业务与回归文件合计 552 行新增、1231 行删除，净减少 679 行。

## DeepSeek V4 延迟与稳定性优化

- 请求显式设置 `thinking: { type: "disabled" }`，紧凑输出上限为 900 token，并使用原生 `AbortSignal` 设置 15 秒超时；OpenAI 同样增加 15 秒超时和候选真值落地校验。
- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/) 说明 V4 thinking 默认启用，并支持通过 `thinking.type` 切换为 `disabled`；[Chat Completion API](https://api-docs.deepseek.com/api/create-chat-completion/) 记录了 thinking、`max_tokens` 与 JSON 输出参数。
- 最终 6 个真实样例覆盖手机、平板、电脑及预算边界与正常推荐：6/6 为 `source=ai`，0 fallback、0 retry，平均 2862.7ms、P95 3631.5ms。
- 优化前 4 个对照样例只有 1 AI / 3 rules，retryRate 为 100%，平均 13735.3ms、P95 25806.7ms；正常推荐单例由 24.4 秒 rules fallback 改善为 3.1 秒 AI 一次成功。

## 风险与边界

- 设备身份与价格已强制从本地候选真值补齐；模型生成的自然语言理由仍主要依赖 Prompt 约束，尚未做逐句事实语义校验。
- 预算使用 `currentPrice → usedPrice → launchPrice` 的已收录价格优先级；当前数据主要为中国大陆首发价，不代表实时市场价。
- 6 个真实样例说明本次改动显著改善，不代表 DeepSeek 长期稳定；15 秒超时和完整 rules fallback 保留。
